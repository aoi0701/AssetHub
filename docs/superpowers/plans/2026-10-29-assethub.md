# Kế hoạch triển khai AssetHub

Ngày cập nhật: 2026-10-29. Trạng thái: chưa triển khai ứng dụng. Chỉ đánh dấu checkbox khi đã có kết quả thực chạy.

**Spec nguồn:** [2026-10-29-assethub-design.md](../specs/2026-10-29-assethub-design.md). Thực hiện task theo thứ tự phụ thuộc. Có thể dùng `superpowers:executing-plans` khi môi trường đã cài. Thay hợp đồng phải sửa đồng thời spec, task và tests; không tự thêm phạm vi ngoài V1.

**Mục tiêu:** Django REST Framework + PostgreSQL + React, Docker Compose, JWT/RBAC, nghiệp vụ tài sản, Swagger/Postman, biểu đồ và Cloudflare Hybrid trong bốn tuần. Backend máy demo qua Tunnel; frontend Pages; R2 riêng tư; Django proxy đến Worker/Workers AI; D1 chỉ lưu log AI.

## 1. Quy tắc thực hiện

- Task 0 cấu hình runner trước. Với task tính năng: viết test hành vi → chạy và xác nhận thất bại đúng lý do → triển khai → chạy lại test và hồi quy bị ảnh hưởng. Thiếu cấu hình pytest/npm không phải bằng chứng test nghiệp vụ thất bại đúng.
- Mọi lệnh bên dưới chạy từ root. Backend container có working directory `/app`, source backend copy vào `/app`, import `apps.*`; pytest config ở backend. Tests chạy PostgreSQL test database; không thay SQLite cho kiểm chứng transaction/khóa.
- Base `docker-compose.yml` có db/backend, không publish port hoặc bind mount source. Dev override mở backend localhost, mount `./backend:/app` để code/migrations/schema đồng bộ workspace và thêm frontend ở Task 8. Prod override chỉ ghép base, không ghép file dev; project `assethub-demo`/env `.env.demo` riêng để không đụng DB local.
- Chưa có Git: Task 0 tạo repo/ignore trước. Mỗi task kiểm staged diff rồi commit khi kiểm chứng đạt. Không push/publish chỉ vì đang chỉnh tài liệu.
- Mock external services trong unit tests. Kiểm chứng R2/AI/D1 thật là bước riêng, cần credentials hợp lệ. Thiếu tài khoản/domain không được ghi tích hợp thành công.
- Sau mỗi task ghi command, exit code, ngày và kết quả đã che secret vào `docs/verification-report.md`. Raw reports chứa token để trong `test-results/` gitignored.

### Ràng buộc bắt buộc

1. Đăng ký chờ Admin kích hoạt; không tự chọn role/phòng ban. JWT access/refresh kiểm tra user DB, `is_active`, `auth_version`.
2. Asset mới AVAILABLE; generic PATCH không sửa trạng thái/mã/phòng ban/người giữ. Action dùng chung AssetService theo spec §5.
3. Transaction và lock theo thứ tự Request → Asset; kiểm tra lại sau lock; asset/request/log cùng commit hoặc rollback. Race/phiếu đã xử lý trả 409.
4. Scope áp dụng cho list/detail/action/FK/history/report/file ở Django. Không xóa cứng Asset/User/history; không tin role hoặc requester do client gửi.
5. Lịch sử cá nhân từ log liên quan bản thân, độc lập tài sản hiện giữ. File private, URL ký 60 giây sau kiểm tra quyền.
6. Browser chỉ gọi AI qua Django; secret chỉ ở server; lỗi AI/D1 không chặn nghiệp vụ chính.
